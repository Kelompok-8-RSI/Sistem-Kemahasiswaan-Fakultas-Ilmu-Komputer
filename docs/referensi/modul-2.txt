pengguna tersebut sesuai dengan teori use case diagram. Gunakan user story di atas serta

Use Case Specification UC-01
      Use Case ID: UC-01
   Use Case Name: Login ke Sistem
         Created By: AA                                  Last Updated By: AA
     Date Created: 01/10/2026                          Date Last Updated: 01/10/2026


                          Actor: Pengguna (Mahasiswa/Staf Kemahasiswaan/Pejabat terkait)
                  Description: Use case ini menggambarkan proses pengguna melakukan autentikasi
                               menggunakan username dan password sebelum dapat mengakses fitur-fitur
                               di dalam sistem sesuai perannya.
                Usecase Goal: Sistem dapat mengenali identitas dan peran pengguna secara aman,
                               sehingga akses fitur yang diberikan sesuai wewenang masing-masing peran.
                Preconditions: Pengguna telah memiliki akun (username dan password) yang terdaftar di
                               sistem.
                   Main Flow: 1. Pengguna membuka halaman login.
                               2. Sistem menampilkan form login berisi kolom username dan password.
                               3. Pengguna memasukkan username dan password.
                               4. Pengguna menekan tombol "Login".
                               5. Sistem memvalidasi kombinasi username dan password ke database.
                               6. Sistem mengenali peran akun (Mahasiswa/Staf Kemahasiswaan/Pejabat).
                               7. Sistem mengarahkan Pengguna ke dashboard sesuai peran akunnya.
         Alternative Flow - 1: Pada langkah 5, jika kombinasi username dan password tidak sesuai, sistem
                               menampilkan pesan error "Username atau password salah" dan
                               mengembalikan Pengguna ke langkah 3 untuk mencoba kembali.
         Alternative Flow - 2: Pada langkah 3, jika Pengguna menekan tautan "Lupa Password", sistem
                               mengarahkan Pengguna keluar dari alur use case ini menuju proses
                               pemulihan akun, sebelum Pengguna dapat kembali melanjutkan ke langkah
                               4.
              Postconditions: Pengguna berhasil masuk ke sistem dengan sesi aktif dan akses fitur sesuai
                               perannya.

Use Case Specification UC-02
      Use Case ID: UC-02
   Use Case Name: Melihat dan Memperbarui Data Profil
       Created By: AT                                   Last Updated By: AT
     Date Created: 1/10/2026                         Date Last Updated: 1/10/2026


                        Actor: Pengguna (Mahasiswa/Staf Kemahasiswaan/Pejabat terkait)
                Description: Use case ini menggambarkan proses Pengguna melihat data identitasnya
                             (nama, NIM/NIP, email, dan nomor telepon) pada halaman profil, kemudian
                             memperbarui data tersebut apabila diperlukan. Sistem memvalidasi
                             perubahan sebelum menyimpannya ke database.
              Usecase Goal: Pengguna dapat memastikan data identitasnya selalu akurat dan terbaru,
                             sehingga data yang dipakai sistem pada setiap pengajuan, verifikasi, dan
                             pengiriman dokumen sesuai.
              Preconditions: Pengguna telah login ke dalam sistem (UC-01).
                  Main Flow: 1. Pengguna membuka menu profil.
                               2. Sistem menarik data identitas Pengguna dari database.
                               3. Sistem menampilkan halaman profil yang memuat nama, NIM/NIP, email,
                               dan nomor telepon.
                               4. Pengguna mengubah data profil yang perlu diperbarui.
                               5. Pengguna menekan tombol "Simpan".
                               6. Sistem memvalidasi perubahan data profil.
                               7. Sistem menyimpan perubahan data profil ke database.
                               8. Sistem menampilkan notifikasi bahwa perubahan berhasil disimpan
                               beserta data profil terbaru.
         Alternative Flow - 1: Pada langkah 4, jika Pengguna tidak ingin mengubah data profil, Pengguna
                               menekan tombol "Tutup" dan use case selesai tanpa perubahan data.
         Alternative Flow - 2: Pada langkah 6, jika data yang diubah tidak valid (misalnya format email
                               tidak sesuai atau kolom wajib kosong), Sistem menampilkan notifikasi gagal
                               perubahan dan mengembalikan Pengguna ke langkah 4 untuk memperbaiki
                               data.
              Postconditions: Data profil terbaru tersimpan di database dan ditampilkan pada antarmuka.
                               Jika Pengguna tidak melakukan perubahan, data profil tidak berubah.



Use Case Specification UC-03
      Use Case ID: UC-03
   Use Case Name: Memilih Jenis Dokumen Kemahasiswaan
       Created By: AA                                   Last Updated By: AA
     Date Created: 29/9/2026                         Date Last Updated: 01/10/2026


                        Actor: Mahasiswa
                Description: Use case ini menggambarkan proses Mahasiswa memilih jenis dokumen
                             kemahasiswaan yang akan diajukan melalui dropdown kategori dan
                             sub-kategori yang terstruktur, sebelum diarahkan ke form pengajuan yang
                             sesuai.
               Usecase Goal: Mahasiswa dapat menemukan dan memilih jenis dokumen yang tepat sesuai
                             kebutuhannya tanpa harus mencari-cari di antara banyak tautan form
                             terpisah.
              Preconditions: Mahasiswa telah login ke sistem (UC-01).
                  Main Flow: 1. Mahasiswa membuka menu "Ajukan Dokumen".
                               2. Sistem menampilkan dropdown kategori kebutuhan (Lomba, Beasiswa,
                               Organisasi, Akademik/PKL, Lainnya).
                               3. Mahasiswa memilih salah satu kategori.
                               4. Sistem menampilkan sub-dropdown jenis dokumen spesifik sesuai
                               kategori yang dipilih, beserta ringkasan singkat (deskripsi, estimasi waktu
                               proses, kebutuhan legalisasi).
                               5. Mahasiswa memilih jenis dokumen yang sesuai.
                               6. Mahasiswa menekan tombol "Lanjutkan".
                               7. Sistem menyimpan jenis dokumen terpilih sebagai bagian dari record
                               pengajuan baru.
                               8. Sistem mengarahkan Mahasiswa ke form pengajuan (UC-04) sesuai jenis
                               dokumen terpilih.
         Alternative Flow - 1: Pada langkah 3, jika kategori yang dipilih tidak memiliki jenis dokumen yang
                               sesuai kebutuhan Mahasiswa, Mahasiswa dapat kembali ke langkah 2 dan
                               memilih kategori "Lainnya", atau menghubungi WA Center Kemahasiswaan
                               untuk bantuan lebih lanjut.
         Alternative Flow - 2: Pada langkah 5, jika Mahasiswa ingin mengubah kategori yang sudah dipilih
                               sebelumnya, Mahasiswa dapat menekan tombol "Kembali" untuk kembali ke
                               langkah 3.
              Postconditions: Jenis dokumen terpilih tersimpan sebagai bagian dari record pengajuan baru
                               dan form pengajuan yang sesuai ditampilkan kepada Mahasiswa.

Use Case Specification UC-04
      Use Case ID: UC-04
   Use Case Name: Mengunggah Persyaratan Dokumen Pengajuan
       Created By: AA                                   Last Updated By: AA
     Date Created: 29/9/2026                          Date Last Updated: 29/9/2026


                        Actor: Mahasiswa
                 Description: Use case ini menggambarkan proses Mahasiswa melihat daftar persyaratan
                               wajib untuk jenis dokumen yang telah dipilih, serta mengunggah seluruh
                               lampiran yang diperlukan dalam satu tampilan sebelum submit pengajuan.
               Usecase Goal: Mahasiswa dapat memastikan kelengkapan berkas sebelum submit,
                               sehingga tidak perlu melakukan revisi karena kurang lampiran dapat
                               diminimalkan.
               Preconditions: Mahasiswa telah menyelesaikan use case "Memilih Jenis Dokumen
                               Kemahasiswaan" (UC-03), dan jenis dokumen telah tersimpan pada record
                               pengajuan.
                  Main Flow: 1. Sistem menampilkan daftar persyaratan wajib sesuai jenis dokumen yang
                               telah dipilih Mahasiswa pada UC-03.
                               2. Mahasiswa mengunggah file lampiran untuk item persyaratan pertama.
                               3. Sistem memvalidasi format dan ukuran file yang diunggah.
                               4. Sistem menandai item persyaratan tersebut berstatus "terunggah".
                               5. Mahasiswa mengulangi langkah 2-4 untuk setiap item persyaratan yang
                               tersisa.
                               6. Sistem mengaktifkan tombol "Submit" setelah seluruh item persyaratan
                               wajib berstatus "terunggah".
                               7. Mahasiswa meninjau kembali seluruh lampiran yang telah diunggah.
                               8. Mahasiswa menekan tombol "Submit".
                               9. Sistem menyimpan pengajuan dengan status "Menunggu Verifikasi".
                               10. Sistem meneruskan pengajuan secara otomatis ke antrean Staf
                               Kemahasiswaan.
                               11. Sistem menampilkan pesan konfirmasi kepada Mahasiswa bahwa
                               pengajuan berhasil dikirim.
         Alternative Flow - 1: Pada langkah 3, jika format atau ukuran file yang diunggah tidak sesuai
                               ketentuan, sistem menolak file tersebut dan menampilkan pesan error, lalu
                      mengembalikan Mahasiswa ke langkah 2 untuk mengunggah ulang file yang
                      sesuai.
Alternative Flow - 2: Pada langkah 8, jika Mahasiswa menekan submit namun masih ada item
                      persyaratan wajib yang belum terunggah, sistem mencegah pengiriman dan
                      menampilkan penanda pada item yang masih kosong, mengarahkan
                      Mahasiswa kembali ke langkah 2.
     Postconditions: Paket pengajuan dengan lampiran lengkap tersimpan berstatus "Menunggu
                      Verifikasi" dan diteruskan ke Staf Kemahasiswaan.
Use Case Specification UC-05
      Use Case ID: UC-05
   Use Case Name: Mencantumkan Tenggat Kebutuhan pada Pengajuan Dokumen
       Created By: AT                                   Last Updated By: AT
     Date Created: 1/10/2026                          Date Last Updated: 1/10/2026


                        Actor: Mahasiswa
                 Description: Use case ini menggambarkan proses Mahasiswa mencantumkan tanggal
                               tenggat kebutuhan dokumen pada form pengajuan. Sistem memvalidasi
                               tanggal tersebut (tidak boleh lebih awal dari tanggal pengajuan),
                               menampilkan peringatan apabila sisa waktu kurang dari tiga hari kerja, lalu
                               menyimpan tanggal tenggat bersama data pengajuan.
               Usecase Goal: Mahasiswa dapat mencantumkan tanggal tenggat kebutuhan dokumennya
                               secara valid pada pengajuan, sehingga urgensi pengajuan diketahui Staf
                               Kemahasiswaan dan dokumen dapat diproses sebelum tenggat terlewat.
               Preconditions: Mahasiswa telah login ke dalam sistem (UC-01) dan telah memilih jenis
                               dokumen sehingga form pengajuan ditampilkan (UC-03).
                  Main Flow: 1. Sistem menampilkan form pengajuan yang memuat kolom tanggal tenggat
                               kebutuhan.
                               2. Mahasiswa mengisi form pengajuan.
                               3. Mahasiswa memilih tanggal tenggat kebutuhan.
                               4. Mahasiswa mengirim form pengajuan (submit bersama lampiran
                               persyaratan dari UC-04).
                               5. Sistem memvalidasi tanggal tenggat dengan membandingkannya terhadap
                               tanggal pengajuan.
                               6. Sistem menghitung sisa hari kerja antara tanggal pengajuan dan tanggal
                               tenggat, sisa waktu minimal tiga hari kerja sehingga tidak ada peringatan.
                               7. Sistem menyimpan tanggal tenggat bersama data pengajuan.
                               8. Sistem meneruskan pengajuan ke antrean verifikasi Staf Kemahasiswaan.
         Alternative Flow - 1: Pada langkah 5, jika tanggal tenggat lebih awal dari tanggal pengajuan,
                               Sistem menolak tanggal tersebut dan menampilkan pesan error. Mahasiswa
                               memperbaiki tanggal tenggat (kembali ke langkah 3).
         Alternative Flow - 2: Pada langkah 6, jika sisa waktu kurang dari tiga hari kerja, Sistem
                               menampilkan peringatan tenggat mendesak. Mahasiswa dapat memperbaiki
                               tanggal tenggat (kembali ke langkah 3) atau tetap melanjutkan sehingga
                               Sistem melanjutkan ke langkah 7.
              Postconditions: Pengajuan tersimpan beserta tanggal tenggat kebutuhan dan masuk ke
                               antrean verifikasi Staf Kemahasiswaan dengan status "Menunggu Verifikasi".

Use Case Specification UC-06
      Use Case ID: UC-06
   Use Case Name: Melihat Antrean Pengajuan Berdasarkan Prioritas Tenggat
       Created By: AT                                   Last Updated By: AT
     Date Created: 1/10/2026                          Date Last Updated: 1/10/2026


                        Actor: Staf Kemahasiswaan
                 Description: Use case ini menggambarkan proses Staf Kemahasiswaan melihat daftar
                              antrean pengajuan dokumen yang secara otomatis dihitung sisa waktu
                              tenggatnya, diurutkan secara ascending (tenggat terdekat di atas), dan diberi
                              label visual prioritas.
               Usecase Goal: Staf Kemahasiswaan dapat memprioritaskan pemrosesan dokumen yang
                              batas waktunya paling mendesak (misalnya tenggat lomba mahasiswa).
               Preconditions: Staf Kemahasiswaan telah login ke dalam sistem (UC-01) dan terdapat
                              pengajuan mahasiswa yang memiliki tanggal tenggat (UC-05).
                  Main Flow: 1. Staf Kemahasiswaan membuka daftar antrean pengajuan pada dashboard.
                              2. Sistem mengambil seluruh data antrean pengajuan dari database.
                              3. Sistem menghitung sisa waktu (countdown) antara waktu saat ini dan
                              tanggal tenggat setiap pengajuan.
                              4. Sistem mengurutkan antrean secara ascending berdasarkan sisa waktu
                               (tenggat paling dekat di atas).
                               5. Sistem memberi label prioritas: merah untuk sisa waktu kurang dari 3 hari,
                               kuning untuk 3 sampai dengan 7 hari, dan hijau untuk lebih dari 7 hari.
                               6. Sistem menampilkan tabel antrean yang telah terurut beserta label
                               prioritasnya.
                               7. Staf Kemahasiswaan melihat daftar antrean dan memproses pengajuan
                               mulai dari urutan paling atas.
         Alternative Flow - 1: Pada langkah 2, jika tidak terdapat pengajuan dalam antrean, Sistem
                               menampilkan pesan bahwa antrean kosong dan use case selesai.
         Alternative Flow - 2: Pada langkah 5, jika tanggal tenggat sudah terlewat (sisa waktu nol atau
                               negatif), Sistem memberi label merah dengan keterangan "Terlewat" dan
                               menempatkannya di urutan paling atas.
              Postconditions: Daftar antrean pengajuan yang terurut berdasarkan sisa waktu tenggat
                               beserta label prioritasnya ditampilkan kepada Staf Kemahasiswaan.

Use Case Specification UC-07
      Use Case ID: UC-07
   Use Case Name: Memvalidasi Kelengkapan Lampiran Pengajuan Dokumen
       Created By: JA                                    Last Updated By: JA
     Date Created: 1/10/2026                          Date Last Updated: 1/10/2026


                        Actor: Staf Kemahasiswaan
                 Description: Staf Kemahasiswaan membuka detail pengajuan yang sudah disubmit.
                               Sistem menampilkan daftar persyaratan lampiran beserta status unggah dan
                               checklist validasi. Staf memeriksa tiap lampiran dan menandainya lengkap
                               atau tidak lengkap lalu sistem menyimpan hasil validasi.
               Usecase Goal: Kelengkapan lampiran diperiksa secara jelas dan terstruktur sebelum
                               pengajuan diproses ke tahap selanjutnya.
               Preconditions: Staf telah login (UC-01). Pengajuan berstatus "Menunggu Verifikasi" sudah
                               masuk antrean (UC-04, UC-06).
                  Main Flow: 1.​ Staf memilih satu pengajuan dari antrean dan membuka halaman
                                    detailnya.
                               2.​ Sistem menampilkan data pengajuan, daftar persyaratan lampiran wajib
                                    sesuai jenis dokumen, status unggah tiap item (sudah/belum diunggah),
                                    dan checklist dengan status awal “Belum Diperiksa”
                               3.​ Staf membuka dan memeriksa lampiran satu per satu.
                               4.​ Staf menandai item sebaai “Lengkap” jika sesuai ketentuan.
                               5.​ Sistem menyimpan status validasi item beserta ID staf dan timestamp
                                    lalu memperbarui tampilan checklist tanpa memuat ulang halaman.
                               6.​ Staf mengulangi langkah 3-5 sampai seluruh item selesai diperiksa.
                               7.​ Sistem mengevaluasi status validasi seluruh item dan menetapkan hasil
                                    validasi pengajuan “Lengkap”
                               8.​ Sistem mengizinkan pengajuan dilanjutkan ke tahap berikutnya (status
                                    diubah melalui UC-08) dan menampilkan konfirmasi bahwa validasi
                                    tersimpan.
         Alternative Flow - 1: Pada langkah 4, jika lampiran tidak sesuai ketentuan, Staf menandai item
                               "Tidak Lengkap" dan mengisi catatan alasan. Sistem menyimpan penandaan
                               tersebut dan alur kembali ke langkah 6. Pada langkah 7, jika ada minimal
                               satu item "Tidak Lengkap", sistem menetapkan hasil "Tidak Lengkap" dan
                               menyarankan Staf mengubah status ke "Revisi" beserta catatan (UC-08).
         Alternative Flow - 2: Pada langkah 2, jika ada item wajib yang belum diunggah, sistem menandai
                               item "Belum diunggah" dan menonaktifkan opsi "Lengkap" pada item
                               tersebut. Item otomatis dianggap "Tidak Lengkap" dan alur berlanjut ke
                               langkah 6.
              Postconditions: Status validasi tiap item tersimpan di database beserta ID staf dan
                               timestamp. Hasil validasi pengajuan ("Lengkap"/"Tidak Lengkap") tampil
                               pada halaman detail.
Use Case Specification UC-08
      Use Case ID: UC-08
   Use Case Name: Memperbarui Status Pengajuan Dokumen
       Created By: MR                                     Last Updated By: MR
     Date Created: 1/10/2026                            Date Last Updated: 1/10/2026


                       Actor: Staff Kemahasiswaan
                 Description: Use case ini menggambarkan proses Staf Kemahasiswaan memperbarui
                               status pengajuan dokumen. Sistem mendeteksi jenis dokumen dan hanya
                               menampilkan opsi status yang sesuai jalurnya (alur standar atau alur
                               legalisasi). Setiap perubahan status dicatat otomatis ke log riwayat beserta
                               timestamp.
               Usecase Goal: Status pengajuan selalu akurat dan mengikuti jalur yang tepat, sehingga
                               riwayat pemrosesan tercatat terarah dan dapat dipantau mahasiswa.
               Preconditions: Staf Kemahasiswaan telah login ke sistem (UC-01). Pengajuan mahasiswa
                               sudah masuk ke antrean dan tidak berstatus "Selesai".
                  Main Flow: 1. Staf Kemahasiswaan membuka halaman detail pengajuan dari daftar
                               antrean.
                               2. Sistem membaca jenis dokumen berdasarkan ID Pengajuan.
                               3. Sistem menampilkan dropdown status tahapan yang sesuai jalur dokumen
                               (alur standar: Menunggu Verifikasi, Sedang Diproses, Revisi, Selesai; alur
                               legalisasi: ditambah Menunggu Legalisasi Pejabat).
                               4. Staf memilih status tahapan baru.
                               5. Sistem memvalidasi bahwa status yang dipilih termasuk opsi yang
                               diizinkan untuk jalur dokumen tersebut.
                               6. Sistem menyimpan status baru pada pengajuan.
                               7. Sistem mencatat perubahan status beserta timestamp sebagai baris baru
                               pada log riwayat.
                               8. Sistem menampilkan status terbaru pada halaman detail pengajuan,
                               sehingga dapat dilihat mahasiswa.
         Alternative Flow - 1: Pada langkah 4, jika Staf memilih status "Revisi", Sistem menampilkan kolom
                               catatan perbaikan yang wajib diisi. Staf mengisi catatan, lalu alur berlanjut ke
                               langkah 5. Jika catatan kosong, Sistem menolak penyimpanan dan
                               menampilkan pesan error.
         Alternative Flow - 2: Pada langkah 4, jika dokumen berjalur legalisasi dan Staf memilih
                               "Menunggu Legalisasi Pejabat", Sistem menyimpan status tersebut dan
                               meneruskan pengajuan ke antrean akun Pejabat Fakultas (UC-09)
              Postconditions: Status pengajuan diperbarui sesuai jalur dokumen yang tepat, dan satu baris
                               baru (status, timestamp) tersimpan di log riwayat.

Use Case Specification UC-09
      Use Case ID: UC-09
   Use Case Name: Memberikan Keputusan Legalisasi Dokumen oleh Pejabat
       Created By: MR                                     Last Updated By: MR
     Date Created: 1/10/2026                            Date Last Updated: 1/10/2026


                       Actor: Pejabat Fakultas
                Description: Use case ini menggambarkan proses Pejabat Fakultas meninjau pengajuan
                             dokumen yang berstatus "Menunggu Legalisasi Pejabat", lalu memberikan
                             keputusan persetujuan (approve) atau penolakan (reject). Penolakan wajib
                             disertai catatan alasan. Keputusan tersimpan resmi di sistem dan status
                             dokumen diperbarui otomatis.
