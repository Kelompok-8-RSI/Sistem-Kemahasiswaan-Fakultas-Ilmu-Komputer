## 3.0 Software Architecture

Sistem dibangun sebagai satu aplikasi **Spring Boot** (Java 17\) dengan arsitektur berlapis (layered architecture) berbasis pola MVC di sisi server. Antarmuka dirender oleh Thymeleaf pada aplikasi yang sama, sehingga tidak ada frontend atau API yang terpisah. Pembagian lapisannya mengikuti pemodelan Boundary \- Control \- Entity pada Modul 2: lapisan Boundary adalah halaman Thymeleaf, lapisan Control adalah pasangan Controller (Spring MVC) dan Service, sedangkan lapisan Entity adalah Repository (Spring Data JPA) dan kelas Entity (JPA) yang dipetakan ke tabel pada Physical Data Model.

**Gambar 3.1 Arsitektur Sistem**

| Browser (Mahasiswa, Staf Kemahasiswaan, Pejabat) |
| :---- |
| BOUNDARY (View): template Thymeleaf login, form-tenggat, antrean, checklist, legalisasi-antrean, legalisasi-detail; AuthInterceptor sebagai gerbang sesi dan peran |
| CONTROL: Controller (Spring MVC) memanggil Service (aturan bisnis) |
| ENTITY: Repository (Spring Data JPA) dan Entity JPA yang dipetakan ke tabel pada PDM |
| MySQL 8 (database/schema.sql) dan file system (folder uploads) |

*Gambar 3.1 menunjukkan arah pemanggilan dari lapisan paling atas ke paling bawah. Urutan langkahnya dijelaskan pada bagian Alur di bawah.*

**Alur**

1. Pengguna membuka halaman melalui browser; permintaan HTTP (form biasa atau fetch untuk validasi lampiran) dikirim ke aplikasi Spring Boot.  
2. AuthInterceptor mencocokkan sessionToken pada sesi dengan AkunPengguna.sessionToken di database, lalu memeriksa peran (Mahasiswa, Staf Kemahasiswaan, Pejabat) terhadap anotasi @RequiredRole. Jika gagal, pengguna diarahkan ke halaman login atau menerima status 403\.  
3. DispatcherServlet meneruskan permintaan ke controller (Control), yang memanggil method pada service sesuai pseudo-code pada Modul 2\.  
4. Service menjalankan logika bisnis dan memakai repository (Entity), yang membaca dan menulis data ke MySQL melalui JPA.  
5. Hasil dikembalikan ke controller, yang mengisi Model lalu memilih nama view Thymeleaf atau melakukan redirect.  
6. Thymeleaf merender HTML pada View (Boundary) dan mengirimkannya sebagai respons ke browser.

**Menjalankan Aplikasi**

1. Buat basis data dengan menjalankan database/schema.sql pada MySQL 8, lalu isi akun awal dengan password yang di-hash bcrypt.  
2. Atur variabel lingkungan DB\_HOST, DB\_NAME, DB\_USER, DB\_PASSWORD, dan UPLOAD\_DIR jika berbeda dari nilai bawaan pada application.properties.  
3. Jalankan mvn spring-boot:run, lalu buka http\://localhost:8080/login.

**Penyesuaian terhadap Pseudo-Code Modul 2**

* Tipe ID mengikuti DDL (INT), sehingga parameter idPengajuan bertipe Integer pada seluruh method, termasuk method yang pada Modul 2 bertipe String.  
* PC-29 (hitungHasilValidasi) menerima daftar ItemChecklist hasil susunChecklist, bukan seluruh lampiran. Dengan begitu persyaratan wajib yang belum diunggah ikut dihitung dan lampiran lama berstatus Diganti tidak terhitung.  
* Ditambahkan pemeriksaan pengaman: Mahasiswa hanya dapat mengisi tenggat pada pengajuannya sendiri; tanggal pada PC-20 divalidasi ulang; lampiran pada PC-27 harus milik pengajuan yang dibuka; dan keputusan legalisasi pada PC-34 hanya berlaku untuk pengajuan berstatus Menunggu Legalisasi Pejabat.  
* Method requestAntreanLegalisasi (antrean Pejabat, MR-SR-18) dan BerkasController (tombol Buka Lampiran) ditambahkan karena dibutuhkan oleh UI-07 dan UI-09.  
* Kartu Riwayat dan kolom Diteruskan pada UI-09 memakai log RiwayatStatus (findByIdPengajuanOrderByWaktu) yang dilengkapi nama dan peran pelaku melalui DTO LangkahRiwayat dan BarisLegalisasi.
